# 事实与工具结果的字段级校验

旧实现只检查 `evidence_tool` 是否在调用列表中。即使工具返回销售额 30，模型仍可把 999999 写成 `fact`。现在工具名只是辅助信息，事实必须通过具体字段核对。

## 证据契约

每次实际调用由服务端分配本轮唯一编号，例如 `call_1`。编号对应决策轮数，因此失败调用也占编号；相同参数的缓存复用保持原编号。步骤及模型观察值都带编号，成功步骤保存包含默认值的工具参数，用于核对聚合口径、排序和时间粒度。

模型返回的单条事实示例：

```json
{
  "statement": "B 的销售额为 30。",
  "claim_type": "fact",
  "evidence_tool": "find_top_n",
  "evidence": [
    {"call_id": "call_1", "result_path": "/rows/0/product", "value": "B", "unit": "source"},
    {"call_id": "call_1", "result_path": "/rows/0/sales", "value": 30, "unit": "source"}
  ]
}
```

`result_path` 是相对于工具返回 `data` 的 JSON Pointer。对象键中的 `/`、`~` 分别写作 `~1`、`~0`；字段名中的点保持原样。路径只做字典取值和非负列表索引，不执行表达式，也不访问 Python 属性。

校验通过后，`statement` 会被替换成程序生成的摘录：

```text
call_1 /rows/0/product = "B"; call_1 /rows/0/sales = 30
```

任意模型自然语言都不会被认证为已核实事实。即使引用值正确，原句中的错误对象、单位、原因或范围也不会混进事实文本。界面以纯文本渲染摘录，防止单元格内容被解释成 Markdown 链接或徽章；展开证据可查看调用编号、字段、值、单位和该调用的完整参数。分组和时期应与其度量一起引用；每个字段都有明确的调用与行索引。

## 数值、单位和失败边界

- 只接受本轮成功执行的真实结果。失败调用、无结果或不可用的知识检索、其他运行的结果都不能作证据。
- 逐字段检查值；数值 `30` 和 `30.0` 相等，但字符串 `"30"`、布尔值与数值不互换。空值、非有限值和容器不作为事实标量。
- 默认按十进制值精确比较，不接受模型自定的误差容限。需要展示舍入值时显式提供 `decimal_places`（0–6），使用十进制 `ROUND_HALF_UP`，界面摘录会标明舍入位数。
- `percent` 仅用于工具契约定义的百分数字段，`5` 表示 `5%`；`count` 用于契约定义的计数字段；其余使用 `source`，表示沿用源字段单位。不会从字段名猜人民币、美元或把比例自动乘 100。
- 单条事实最多 4 个引用、生成文本最多 500 字符。引用缺失、格式错误、编号错误、工具名冲突、路径不存在、值或单位不匹配、任一引用无效、文本超限，整条降级为 `hypothesis` 并清空证据标记。兼容旧版仅有工具名的回答，但同样降级，不会中断整轮分析。
- 完整工具结果只在本轮校验期间保留，不因模型观察值的截断而丢失。引用与选中标量随 AgentResponse 留在当前会话，不增加 MySQL、Qdrant 或 LangSmith 正文写入。

## 保证与限制

本功能保证的是“展示的事实摘录与指定工具结果字段一致”，不保证数据源本身正确，也不判断业务口径是否适合用户的问题。知识片段匹配不代表原文内容真实或相关。尚未由工具计算的比率、差值、排序解释和因果判断只能作为解释或假设；不对自由文本做语义真伪判定。

Executive Summary、Recommendations、解释、假设以及 `final_answer` 原始叙述仍来自模型，界面明确说明它们未经程序校验。真实模型能否稳定遵循新引用契约需单独做在线验收；离线测试通过不能替代这一验证。

## 离线回归

`tests/test_agent_evidence.py` 覆盖合法引用、虚构数字、错行、错调用、失败后恢复、缓存、跨运行隔离、路径转义、严格类型、舍入、百分比与计数单位、截断结果和不可信自然语言。Streamlit AppTest 检查中英文说明、证据参数展示，以及源值不会作为 Markdown 渲染。所有测试不使用真实服务或密钥。
