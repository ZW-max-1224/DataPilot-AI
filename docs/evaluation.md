# 评估说明

[返回项目首页](../README.md) · [事实证据校验](fact-evidence.md)

当前 Evaluation 是一个用于回归的小型评估框架，复用现有 `AnalystAgent.run(AgentRequest)`，不会另建 Agent 循环，也不改变工具或检索策略。

## 运行

1. 在 Streamlit 页面打开 **Evaluation / 评估** 区域。
2. 确认要使用的 LLM、Embedding 与本地知识库可用。
3. 点击运行，检查每个案例的状态与失败原因。
4. 按需下载结构化 JSON 报告。

页面评估会调用已配置的真实模型；这与不联网的 `pytest` 自动化测试不同。LLM Judge 默认关闭，启用后会增加模型调用。

## 案例与结果

固定数据集 [datapilot_mvp_v1.json](../data/evaluation/datapilot_mvp_v1.json) 包含 **15 个案例**，覆盖 Pandas 分析、知识检索与引用、知识与数据联合任务，以及无数据集等执行场景。

案例结果区分 `passed`、`failed`、`skipped` 和 `unavailable`。缺少依赖时单独标记，意外崩溃必须计为失败，不能从通过率分母中移除。各指标保留分子和分母，没有可评估案例时显示 N/A。

| 指标 | 检查内容 |
| --- | --- |
| 工具选择 | 预期工具覆盖、调用精度与不必要调用 |
| 检索 | 预期文档或切片的 Hit@1 / 3 / 5，以及当前定义的 miss |
| 引用 | 引用是否对应实际检索来源，计算 Precision / Recall |
| 数值结果 | 类型和值精确匹配、数值容差或集合比较 |
| 执行行为 | 成功率、未注册工具、重复调用与轮数上限 |
| Grounding | 结构化证据代理指标，不代表任意自然语言语义正确 |

工具调用顺序不作为主要判据，额外调用有独立指标。工具参数也会参与指定真值的匹配。

## 真值与已知局限

当前部分 Pandas 期望值来自被测工具自身的历史输出，因此主要用于检测变化，**不是独立的正确性证明**。即使工具输出匹配，模型的最终叙述仍可能不准确。

检索还有一处待统一的定义：当前无关问题案例把返回空结果作为期望，而实际检索不设相似度阈值，可能返回低分候选。后续应检查答案是否正确说明证据不足，而不是要求检索器必须零召回。

下一步优先建立人工核算的小数据与独立标准答案，再扩展错误口径、并列排名、缺失值、错误引用和证据不足场景。指标需区分“计算是否正确”“引用是否有效”和“是否回答了问题”。

## LLM Judge 与数据边界

LLM Judge 经过 Pydantic 校验，单独记录 `judge_status`，仅作为辅助信号，不改变案例通过状态或确定性真值。

本地 JSON 报告保存固定案例问题与脱敏结果元数据，不保存运行时完整答案、DataFrame 或工具证据正文。可选 LangSmith 只记录案例 ID、问题哈希与长度、状态、工具名、检索 ID、指标和耗时等摘要。

离线测试通过、单次模型冒烟和历史端到端验收是不同层级的证据。最新事实校验记录见 [验证记录](fact-evidence.md#本次验证记录2026-10-22)，历史 Agent / RAG 实测见 [真实验收 v2](real_run_acceptance_v2.md)。
